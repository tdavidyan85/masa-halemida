# ארכיטקטורה: קליטת דף מצילום והפיכתו לחבילת תוכן

סטטוס: שלב 1 נבנה בקוד (5.11.2026), עדיין לא הופעל באתר החי. שלבים 2–4 הם כיוון.

## מטרה
הורה מצלם דף עבודה או שיעורי בית ← המערכת מייצרת חבילת תוכן (`masa-pack/1`) ← המבוגר מסקור ומאשר ← הילד משחק עם אותו מנוע, אותה הקראה ואותם מבחנים.
ראו [pack-format.md](pack-format.md) לפורמט החבילה.

## עקרונות
1. **הילד נשאר אנונימי.** אין חשבונות לילדים, וההתקדמות נשארת ב-localStorage במכשיר. שום שם או כתב ילד לא נשלח לשרת (ראו CLAUDE.md).
2. **רק מבוגרים משאירים עקבות בשרת:** תמונה זמנית וחבילה.
3. **החבילה היא החוזה.** מה שנוצר מצילום נבדק ב-`validate-pack` כמו כל חבילה ידנית.
4. **מבוגר מאשר לפני שילד רואה.** ה-AI טועה, וזו גם שכבת הגנה על פרטים אישיים ועל איכות.
5. **עלות מוגבלת.** מכסה חודשית ומכסה לכל בעלים, כמו `TTS_MONTHLY_CAP`.

## זרימה (שלב 1)

```
טלפון
 1. צילום ← כיווץ (עד ~1500px) + הסרת EXIF בדפדפן
 2. שליחה ל-Edge Function `ingest` (גוף הבקשה = התמונה בלבד)
Edge Function `ingest` (מזוהה בקישור עריכה סודי של הבעלים)
 3. Claude API (ראייה) ← טיוטת masa-pack/1 + דגל "נמצאו שמות/פרטים מזהים"
 4. הסרת/החלפת שמות אנשים, בית ספר וטלפונים בטקסט
 5. אימות באותו validator
 6. התמונה נמצאת רק בזיכרון הפונקציה ולא נשמרת בשום מקום (אין דלי אחסון)
עורך סקירה (מבוגר)
 7. תצוגה מקדימה של כל שאלה, עריכה, מחיקה, אישור ← status = approved
המנוע
 8. טעינת חבילה לפי מזהה: `?pack=<id>` ← אותו מנוע
```

## נתונים (Supabase)

| טבלה/דלי | שדות עיקריים | גישה |
|---|---|---|
| `packs` | `id`, `edit_token_hash`, `status` (draft/approved), `json`, `created_at`, `expires_at?` | קריאה: approved לפי `id` בלבד. כתיבה: רק דרך פונקציה עם אסימון עריכה |
| `ingest_usage` | `owner_hash`, `pages`, `tokens`, `month` | פנימי; לבקרת מכסה |

הערות:
- `id` החבילה אקראי וארוך (לא ניתן לניחוש). מי שיש לו את הקישור יכול לשחק. אין רשימה ציבורית.
- אסימון העריכה נשמר כ-hash בלבד.
- אין שדה שם ילד/כיתה בשום טבלה.

## פרטיות: סיכונים ומענה

| סיכון | מענה |
|---|---|
| שם ילד/בית ספר/כתב יד בצילום | הסרת EXIF; הנחיה בממשק לצלם בלי השם; הסרת שמות ע"י המודל ובדיקת regex; סקירת מבוגר |
| **מטמון ה-TTS משותף** (`tts-function.ts`, hash לפי טקסט) | טקסט בחבילה נקי משמות לפני אישור. אחרת פרטי ילד ייכנסו למטמון הגלובלי ול-Azure. בנוסף: לשקול מטמון נפרד לחבילות מצולמות |
| ספק ה-AI | ספק עם אי-אימון על נתונים; שליחת התמונה בלבד, בלי מזהי משתמש; אזור אירופה אם אפשר |
| זכויות יוצרים (ספרי לימוד) | חבילה פרטית לבעלים בקישור סודי; אין ספרייה ציבורית; תנאי שימוש יאמרו זאת |
| ניצול עלות | מכסה חודשית כללית, מכסה לכל בעלים, מגבלת גודל תמונה |
| עריכה בידי אחרים | אסימון עריכה סודי נפרד מקישור המשחק |
| קישור משחק שנחשף | אפשרות ביטול/החלפת הקישור בעורך |

חוק הגנת הפרטיות (כולל תיקון 13) ונתוני קטינים: נדרשת סקירה משפטית לפני פיילוט עם כיתות אמיתיות. מסמך זה אינו חוות דעת משפטית.

## מה נבנה (שלב 1)
| קובץ | תפקיד |
|---|---|
| `src/sql/001_packs_ingest.sql` | טבלאות `packs`, `ingest_usage`, פונקציות מכסה (**טרם הופעל**) |
| `src/ingest-function.ts` | Edge Function `ingest`: `new`, `get`, `save`, `pack`, `delete` (**טרם הופעל**, דורש `ANTHROPIC_API_KEY`) |
| `src/scan.html` ← `/scan/` | צילום, כיווץ והסרת EXIF בדפדפן, עיון ועריכה, אישור, קישור לילד |
| `src/packpage-boot.js`, `src/build_packpage.py` ← `/pack/?pack=<id>` | עמוד המשחק לחבילות מצולמות; `&t=<token>` = תצוגת טיוטה להורה |
| `src/tts-function.ts` | פרמטר `n=p`: מטמון קול נפרד לחבילות מצולמות |
| `src/tests/tpack.js`, `src/tests/tscan.js` | בדיקות דפדפן עם `ingest` מדומה |

פרטי מימוש שחשוב לדעת:
- מזהי נושא וכישור מהמודל (`t1`, `s1`) מקבלים קידומת לפי מזהה החבילה, כדי שהתקדמות של חבילה אחת לא תתערבב באחרת.
- מזהה החבילה (חלק מהקישור הפרטי) לא נשלח לטבלאות המדידה והמשוב (נשלח `pack`), והעמוד מסומן `noindex`.
- אימות מלא של החבילה רץ במנוע האמיתי בעמוד המשחק; בשרת רק בדיקת מבנה (תשובה בתוך האפשרויות, ללא כפילויות).

## הפעלה (דורש אישור)
1. להריץ את `src/sql/001_packs_ingest.sql` בפרויקט Supabase.
2. להגדיר סוד `ANTHROPIC_API_KEY` ולפרוס את `ingest-function.ts` ואת `tts-function.ts` המעודכן.
3. `cd src && npm run publish-site`, commit ו-push.

## עלות הערכה
לדף: כ-7–10K טוקני כניסה (כולל תמונה, ניתן לשמירה במטמון חלקית) וכ-5–8K יציאה. המחיר מתחשב בתמחור המודל הנוכחי; יש לאמת לפני קביעת מנוי.
