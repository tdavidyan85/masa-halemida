## 2. מה באמת יש ב"מפעל השברים" (מהקוד)

- **8 תבניות תרגיל**, כל אחת עם "מכונה" וסיפור קצר. מספרים נבחרים אקראית בכל משחק, לכן אי אפשר לשנן.
- **צביעה אינטראקטיבית:** ציור SVG של עוגייה או שוקולד מחולק ל-d חלקים, לחיצה צובעת, לחיצה נוספת מוחקת. התשובה נבדקת לפי מספר החלקים הצבועים, ואז הילד גם כותב את המספר.
- **ייצוגים מרובים:** אותו כמות מופיעה כמספר מעורב, כשבר גדול משלם, במילים ובציור. התרגילים הם המרות בין הייצוגים:
  - ציור ← מספר ("הסורק")
  - מספר ← ציור (בחירה בין 3 ציורים)
  - מספר ← מילים
  - **טבלה עם תא חסר** ("תעודת המשלוח"): ארבעה ייצוגים בשורה, אחד חסר, והילד משלים אותו
- **הקשר של סיפור:** המפעל, מכונות, משלוחים, נורות התקדמות, מסדרון נע. הכול קישוט, והתרגיל עצמו זהה.
- **משוב:** קונפטי, צליל (כבוי כברירת מחדל), רמז, "פותרים יחד" (חושף פתרון עם הסבר) וניקוד על הצלחה בניסיון ראשון.
- **מה אין שם:** שמירת התקדמות, התאמת קושי, הקראה, מבחנים, דפי הדפסה, מדידה, פורמט חבילה. הכול קשיח לנושא אחד (מספר מעורב ושבר גדול משלם).

**מסקנה:** הכוח שלהם הוא סוגי אינטראקציה וסיפור. הכוח שלנו הוא המערכת (התקדמות, רמות, חזרה מרווחת, הקראה, מבחנים, חבילות). הם משלימים זה את זה.

## 3. מה אומר המחקר (בקצרה)

**IES, מניפולטיבים וירטואליים:**
- תוצאות לימוד דומות או טובות יותר מחומרים פיזיים.
- הייצוג החזותי מתקן טעות נפוצה ("1/5 גדול מ-1/2 כי 5 גדול מ-2") רק אם הוא מדויק ביחס לגודל.
- יתרון דיגיטלי: חלוקה מיידית לכל מכנה (שביעיות, מאיות), הרבה דוגמאות בזמן קצר, ללא מגבלת מוטוריקה, השוואה על ידי הנחה זו על זו.
- המסגרת CRA: קונקרטי (לגעת) ← ייצוגי (ציור) ← מופשט (מספרים). המשחק צריך לעבור בין השלושה.

| הערכה משובצת | יש: רמות, ספירת ניסיונות ראשונים |
| מוטיבציה פנימית + תגמול מינימלי | יש: כוכבים ורצף. תגמולים נשארים צנועים |

הפערים האמיתיים: **חקירה חופשית**, **שייכות**, **אינטראקציה פיזית** (לגעת ולהזיז). הם ברורים יותר מ"עוד סוג שאלה".

## 4. קטלוג אינטראקציות מוצע

אלה סוגי שאלה כלליים (לא רק לשברים) שאפשר להוסיף לפורמט החבילה. כל אחד הוא רכיב SVG/HTML קטן במנוע, והחבילה רק מתארת אותו בנתונים.

| סוג | מה הילד עושה | נושאים | מקור השראה | עלות בנייה |
|---|---|---|---|---|
| `paint` | לוחץ על חלקים וצובע | שברים, אחוזים, שטח, קבוצות, כפל כמערך | מפעל, SplashLearn | נמוכה |
| `match` | מחבר כרטיסים: מספר ↔ ציור ↔ מילים | שברים, אנגלית (מילה ↔ תרגום), שמות גוף | Math Mammoth, No Drama Koala | נמוכה |
| `table` | משלים את התא החסר בשורת ייצוגים | המרות בכל מקצוע | מפעל ("תעודת משלוח") | נמוכה-בינונית |
| `order` | גורר לסידור (קטן ← גדול, שלבי פתרון, משפט) | שברים, מספרים, אנגלית (סדר מילים) | Polypad, SplashLearn | בינונית |
| `numberline` | מניח נקודה על ציר מספרים | שברים, עשרוניים, שלילים | Polypad | בינונית |
| `tap` | לוחץ על המילה או המספר הנכונים בתוך טקסט | אנגלית (מצא את שם הגוף), בעיות מילוליות | Khan Kids | נמוכה |
| `compare` | מניח ציור על ציור (1/4 מול 3/10) | שברים | IES | בינונית |
| `lab` (חופשי) | משחק בלי ציון עם רכיב (חלוקה לכל מכנה) | חקירה | Polypad, Mathigon | בינונית-גבוהה |

### 4א. עיקרון מנחה: מנגנון נפרד מנושא (לכל מקצוע, לא רק חשבון)

הטבלה למעלה נראית כמו חשבון, אבל **כל סוג הוא מנגנון מופשט**. הנושא נכנס רק דרך הנתונים ודרך "תוספי ציור" (renderers) אופציונליים.

**ארבע שכבות, כל אחת עצמאית:**
1. **תוכן:** חבילת `masa-pack` (שאלות, שיעורים). אפשר לכתוב אותה בידיים או לייצר מצילום.
2. **מנגנון אינטראקציה:** מה הילד עושה (בוחר, מחבר, מסדר, ממיין, לוחץ, מציב, משלים). מוגדר בשדה `type` של השאלה.
3. **תוסף ציור (`visual`):** איך נראים הפריטים: טקסט, אימוג'י, SVG מובנה או תוסף נושא (עוגה לשברים, מפה, ציר זמן, כלי מדידה). אם אין תוסף, המנגנון עובד עם טקסט בלבד.
4. **עולם (`theme`):** סיפור וקישוט. מנוע המשחק (כוכבים, רמות, חזרה, הקראה, מבחנים) נשאר זהה לכולם.

**המנגנונים (מוגדרים לפי מה שהילד עושה, לא לפי נושא):**

| מנגנון | תשובה נבדקת כ... | חשבון | אנגלית | עברית / לשון | מדעים / גאוגרפיה / היסטוריה |
|---|---|---|---|---|---|
| `match` חיבור זוגות | מיפוי | מספר ↔ ציור | מילה ↔ תרגום | מילה ↔ הגדרה | מדינה ↔ בירה, אירוע ↔ שנה |
| `sort` מיון לקבוצות | מיפוי לקבוצה | זוגי / אי-זוגי | שם עצם / פועל | שם עצם / שם תואר | יונק / זוחל, מקור אנרגיה |
| `order` סידור | סדר | קטן ← גדול | סדר מילים במשפט | סדר משפטים בסיפור | ציר זמן, שלבי ניסוי |
| `tap` לחיצה בתוך טקסט | קבוצת בחירות | מצא את הנתון | מצא את שם הגוף | מצא את הפועל | מצא את הטענה בקטע |
| `cells` בחירת תאים / חלקים | קבוצת תאים | צביעת שבר | הברות במילה | אותיות בצורת סופית | אזורים במפה (SVG) |
| `place` הצבה על ציר או תרשים | ערך בטווח | ציר מספרים | – | – | ציר זמן, מדחום, קנה מידה |
| `cloze` השלמת חסר | טקסט / בחירה | משוואה | משפט עם מקום ריק | משפט עם מקום ריק | הגדרה עם מקום ריק |
| `choice`, `number`, `spell`, `multi` | כבר קיימים | | | | |

**פירוש לפיתוח:** ההגדרה של "נכון" היא רק אחת מכמה בדיקות כלליות: ערך בודד, קבוצה, סדר, מיפוי, או טווח (יש כבר `accept`). לכן **רמזים, הסבר שלב אחרי שלב, "טעות מסוימת" (`mistakes`), הקראה ומבחנים עובדים אוטומטית לכל מנגנון חדש**, כי הם ברמת השאלה ולא ברמת הנושא.

**דוגמה: אותו מנגנון, שני מקצועות (טיוטת פורמט):**
```jsonc
{ "type": "sort", "text": "לאן שייך כל בעל חיים?",
  "bins": ["יונק", "זוחל"],
  "items": [{ "t": "נחש", "bin": "זוחל" }, { "t": "דולפין", "bin": "יונק" }] }
{ "type": "sort", "text": "<en>Noun or verb?</en>",
  "bins": ["noun", "verb"],
  "items": [{ "t": "run", "bin": "verb" }, { "t": "table", "bin": "noun" }] }
```

**איפה הנושא כן נכנס (תוספי ציור):** שברים (עוגה / שוקולד), ציר מספרים, מפת ישראל, מחוגים. תוסף הוא קובץ קטן שנרשם בשם (`visual: "pie"`), ואם חסר, הילד רואה טקסט. כך אפשר להוסיף נושא חדש בלי לגעת במנגנונים.

**ערבון לפרטיות בצילום דף:** `visual` מאפשר רק טקסט, אימוג'י ותוספים מובנים. אין תמונות מהדף (התמונה לא נשמרת), אז אין גם סיכון לזכויות יוצרים או לפרטים אישיים בתוך הציור.

**איך המודל בצילום יבחר:** הוא יתרגם מטלה בדף למנגנון: "חברו בקו" ← `match`, "הקיפו את הפועל" ← `tap`, "סדרו לפי הסדר" ← `order`, "מלאו את החסר" ← `cloze`, "מיינו לטבלה" ← `sort`. לכן המנגנונים הכלליים מכסים הרבה יותר דפים מאשר סוגי שאלה לפי נושא.

הערות עיצוב:
- **מספרים משתנים:** `vars` שכבר קיים נותן את "מספרים חדשים בכל משחק". צריך שתבניות `paint` ו-`table` יקבלו `vars`.
- **נגישות:** הם משתמשים ב-`role=button` ו-`aria-label` על כל חלק. כדאי כבר מההתחלה.
- **הקראה:** צריך לוודא שכל סוג חדש מקריא את השאלה (ה-TTS שלנו). זה יתרון מובהק שלנו.

## 5. שכבת משחק (סיפור וקישוט)

הצעה: שדה אופציונלי `theme` בחבילה, מלא קישוט בלי קוד:

```jsonc
"theme": {
  "name": "המפעל הקסום",
  "story": { "intro": "המכונות התבלבלו…", "win": "הקסם חזר!" },
  "topics": { "t1": { "title": "רציף ההתאמות", "icon": "◉", "blurb": "התוויות התבלבלו!" } }
}
```

מה זה נותן: אותה חבילה אפשר לעטוף בחלל, בגן חיות או במפעל בלי לשנות תרגילים. הילד בוחר עולם (אוטונומיה וזהות). עלות נמוכה.

מה **לא** לאמץ:
- ניקוד "הצלחה בניסיון ראשון בלבד": הוא מעניש טעות, וזה מנוגד ל"כישלון פורה". אצלנו כבר יש כוכב על "הצלחת בסוף", וזה נכון יותר.
- ללא שמירת התקדמות: ללא זה אין חזרה מרווחת.

## 6. איך זה משתלב עם תוכנית צילום הדף

1. **המודל בוחר מקטלוג סגור.** בהנחיית `ingest` נתאר רק את הסוגים הבטוחים (`choice`, `number`, `fraction`, `spell`, ובהמשך `match`, `tap`). `paint` ו-`table` רק כשהדף על שברים או צורות. סוג חדש = עוד סיכון לאיכות, והמבוגר ממילא מאשר.
2. **העורך של ההורה** (`scan.html`) צריך תצוגה מקדימה לכל סוג חדש. זה סיבה לבנות כל סוג כרכיב אחד שמשרת גם את המשחק וגם את הסקירה.
3. **פרטיות:** אין שינוי. הרכיבים רצים בדפדפן ולא שולחים דבר.
4. **תבנית מול מופע:** מדף עם 8 תרגילי שברים אפשר ליצור תבנית אחת עם `vars` ולקבל אינסוף וריאציות. זה שדרוג גדול על "החבילה היא הצילום".

## 8. הערת זכויות יוצרים

"מפעל השברים" הוא יצירה של תמרה ורדי ("ניצני המדע"), כולל תמונות (`cookie-texture.png`) וסיפור. מותר ללמוד מהרעיונות (צביעה, ייצוגים מרובים, טבלה עם תא חסר), אבל **אין להעתיק קוד, איורים או שמות מכונות**. הרכיבים שלנו ייכתבו מחדש, והסיפור שלנו ייבנה בנפרד. כדאי גם לא להסתמך על דומיין `chatgpt.site`.
