# פורטל מסע הלמידה (הדגמה מקומית)

ממשק משתמשים לארבעה תפקידים: מנהל/ת מערכת, מורה, הורה ותלמיד/ה. React + TypeScript + Vite, עברית מלאה מימין לשמאל, מותאם למחשב ולטלפון.

> **⚠️ זו הדגמה בלבד.** כל השמות והתמונות פיקטיביים. **אין התחברות אמיתית ואין הרשאות מאובטחות**: הכללים רצים בדפדפן ואפשר לעקוף אותם. שום דבר לא נשמר בשרת ולא נשלח לשום שירות.
> מנוע הלמידה הקיים (`src/`, `math/`, `english/`…) לא השתנה. הפורטל רק מקשר אליו.

## הפעלה

```bash
cd portal
npm install
npm run dev          # http://localhost:5173
```

| פקודה | מה היא עושה |
|---|---|
| `npm run dev` | שרת פיתוח עם רענון אוטומטי |
| `npm test` | בדיקות (Vitest + Testing Library) |
| `npm run build` | בדיקת טיפוסים ובנייה ל-`dist/` |
| `npm run preview` | מגיש את `dist/` מקומית |

## מצב שרת (פיתוח בלבד: נבדק מול Supabase מקומי, לא מול ענן)

ברירת המחדל היא הדגמה. חיבור לשרת נפתח **רק** עם הגדרות מלאות ותקינות ב-`.env.local` (ראו `.env.example`):
`VITE_DATA_SOURCE=supabase`, `VITE_SUPABASE_ENV=local|dev`, כתובת ומפתח **ציבורי**.

`src/data/config.ts` עוצר את האפליקציה עם הודעה ברורה כשיש בעיה. הוא דוחה:
- כתובת לא תואמת לסביבה
- את פרויקט האתר החי
- מפתח סודי (service role)
- כל דבר חסר

| יכולת | איך |
|---|---|
| כניסת מבוגרים, הרשמה, אימות דוא״ל, שחזור סיסמה | Supabase Auth (PKCE): `signInWithPassword`, `signUp`, `resetPasswordForEmail`, `updateUser` |
| כניסת תלמידים | הפונקציה `student-login` מחזירה session של Supabase, שעובר ל-`auth.setSession` |
| יצירת חשבון ילד | הפונקציה `manage-student`, להורה מאומת בלבד |
| הזמנות ואישורים | RPC: `create_invitation`, `respond_invitation` |

משימות, התקדמות וציונים עוד לא קיימים במסד הנתונים. במצב שרת הם מוצגים כרשימות ריקות.

## למידה וחומרים

| מי | מה |
|---|---|
| מורה | יוצר/ת משימות (תרגול במנוע, מבחן שנבדק בשרת, קריאה), מפרסם/ת לקבוצה, ורואה התקדמות אמיתית |
| תלמיד/ה | מתרגל/ת במנוע הקיים בתוך הפורטל ועונה על מבחנים |
| הורה | רואה תוצאות, תרגול והיסטוריית למידה |
| מורה והורה | מעלים PDF או תמונה (`/teacher/materials`, `/parent/materials`) |

**המנוע בפורטל:**
- המנוע הקיים מוגש מאותו מקור בכתובת `/play/<מקצוע>/`, בלי שינוי בקוד שלו.
- הפורטל מאזין לקריאות `track()` שלו. שום טוקן לא עובר למנוע או לכתובת.

**חומרים:**
- **חילוץ טקסט:** מ-PDF נעשה במחשב בעזרת pdf.js. מתמונה (OCR) עוד לא נתמך, ומקלידים את הטקסט.
- **המסלול:** נושאים, טיוטה, אישור, ואז מבחן לקבוצה או שיתוף.

## מבנה

```
src/
  data/types.ts          טיפוסים שתואמים לטבלאות המתוכננות (profiles, groups, guardianships, consents…)
  data/source.ts         הממשק היחיד בין המסכים לנתונים (DataSource)
  data/mockSource.ts     מימוש מקומי עם נתונים פיקטיביים, כולל כללי "מי רואה מה"
  data/supabaseSource.ts מקום שמור לחיבור העתידי (לא מחובר, נכשל במפורש)
  data/mockData.ts       הנתונים הפיקטיביים · data/avatar.ts תמונות מצוירות שנוצרות מקומית
  auth/                  הקשר ההתחברות (הדגמה), שומר מסלולים לפי תפקיד, מגביל ניסיונות
  components/            מעטפת וניווט, מצבי טעינה, ריק ושגיאה, רכיבי ממשק
  pages/                 login/ · admin · teacher · parent · student
```

**המעבר לשרת אמיתי:** מממשים את `DataSource` עם supabase-js ומגדירים `VITE_DATA_SOURCE=supabase`. המסכים לא משתנים. כל כלל שמופיע ב-`mockSource.ts` חייב להיאכף בשרת (RLS ופונקציות Edge), והבדיקות ב-`mockSource.test.ts` הן רשימת המקרים שבדיקות ה-RLS צריכות לכסות.
